# Roblox Luau Development Rules

## 1. Язык и типизация
- Пиши весь код исключительно на современном **Luau** (используй расширения файлов `.luau`, `.server.luau`, `.client.luau`).
- В начале **каждого** файла обязательно добавляй директиву `--!strict`.
- Используй строгую типизацию аргументов функций, возвращаемых значений и кастомных типов (`export type PlayerData = { ... }`).
- Не используй устаревшие функции (`wait()`, `spawn()`, `delay()`). Вместо них всегда применяй библиотеку `task`: `task.wait()`, `task.spawn()`, `task.delay()`.

## 2. Архитектура и Rojo
- Проект синхронизируется через Rojo согласно `default.project.json`:
  - `src/server` -> `ServerScriptService.Server`
  - `src/client` -> `StarterPlayer.StarterPlayerScripts.Client`
  - `src/shared` -> `ReplicatedStorage.Shared`
- Избегай создания десятков независимых `Script` и `LocalScript`. Используй единую точку входа (`init.server.luau` и `init.client.luau`), которая подключает `ModuleScript` через `require()`.

## 3. Безопасность (Client-Server Boundary)
- **Никогда не доверяй клиенту.** Вся логика начисления валюты, проверки дистанции, урона, покупок и сохранения данных (`DataStoreService`) выполняется строго на сервере (`src/server`).
- Клиент (`src/client`) отвечает только за UI, анимации, звуки, визуальные эффекты и отправку намерений игрока на сервер через `RemoteEvent` / `RemoteFunction`.
- Любые входящие данные от клиента в `OnServerEvent` должны проходить валидацию типов (`typeof(arg) == "number"` и проверка на `NaN`/бесконечность).

## 4. Проверка качества кода
- После написания или изменения скриптов запускай в терминале линтер `selene src/` и форматтер `stylua src/`, чтобы убедиться в отсутствии синтаксических и логических ошибок до запуска в Roblox Studio.

# Правила проекта (Roblox + Luau + Rojo)

- Весь код только в файлах `src/`. Скрипты в Studio через MCP не править: Rojo перезапишет.
- MCP использовать для: просмотра дерева, создания карты и моделей, свойств, логов, playtest.
- Каждый файл начинается с `--!strict`.
- Сервер авторитетен: урон, инвентарь, крафт, строительство валидируются только на сервере. Клиент отправляет запросы, не результаты.
- Контент (предметы, рецепты, лут) в `src/shared/configs/` как данные, не в логике.
- Сервисы: `src/server/Services/<Name>.luau`, возвращают таблицу с `Init()`.
- Контроллеры клиента: `src/client/Controllers/<Name>.luau`.
- Remote-события: имена в одном модуле `shared/Net.luau`, на сервере проверять тип и диапазон аргументов.
- Данные игрока: ProfileStore.
- Не создавать циклов require.
- Перед началом каждого этапа делать коммит текущего рабочего состояния в Git.
- Не использовать Luau string interpolation (`` `...` ``) в коде `src/` (использовать `string.format(...)`), чтобы `selene` не падал при парсинге.
- Любые изменения объектов в `Workspace` и `Lighting` через MCP выполнять строго в режиме `Edit` (`mode == "Edit"`), никогда во время Playtest.
- Объекты мира на этапах 2–9 делать в стиле Greybox (1–3 примитива на модель, без тяжёлых мешей).
- В конце каждого этапа обновлять `docs/ARCHITECTURE.md` с актуальными публичными сигнатурами сервисов и контроллеров.
