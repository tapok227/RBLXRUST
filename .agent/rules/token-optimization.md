# Token & Context Optimization Rules

- **Карта вместо сканирования:** в начале задачи сначала прочитай `docs/ARCHITECTURE.md`, а не запускай рекурсивный обход (`Get-ChildItem -Recurse`) по `src/`.
- **Запрет на чтение схем MCP:** никогда не читай `.json`-файлы описаний инструментов из `.gemini/mcp/`.
- **Grep только по сигнатурам:** в `Select-String` / `grep_search` ищи только `^(local )?function ` или точные имена событий/типов. Не включай общие слова (`Attribute`, `State`, `Position`, `Death`) и ограничивай вывод в PowerShell (`| Select-Object -First 60`), чтобы не плодить файлы в `.system_generated`.
- **Компактные правки и батчинг:** группируй независимые `read_file` и `edit_file` в один ход. В `edit_file` делай блоки до 40–60 строк (не заменяй куски по 200+ строк за раз, чтобы не ловить промахи по отступам).
- **Сжатый Handoff в `exit_plan_mode` (до 700 слов):** не пересказывай ТЗ и не пиши в план готовый код — указывай только карту `Файл:StartLine-EndLine -> что изменить` и критичные инварианты.
- **Без повторного чтения:** после выхода из Plan Mode не перечитывай диапазоны, уже разобранные в плане, если они не менялись.
